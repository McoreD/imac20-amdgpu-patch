## What it changed

### `AGENTS.md` + `scripts/build-amdgpu.sh`

Bumped `CONFIG_LOCALVERSION` from `-arch2-Watanare-T2-1-t2` to `-arch2-Watanare-T2-4-t2` to match the kernel currently installed on the dev box (and what `repatch-amdgpu.sh` has used since 2026-09-22). Without this bump, modprobe would refuse to load the rebuilt module with a vermagic mismatch.

### `scripts/install-limine-hwaccel-entry.sh`

Refactored so `amdgpu.modeset=1 video=efifb:off` lives in `/etc/default/limine [default]` rather than only on the `imac20-hwaccel` entry. Reasoning (verbatim from script comment):

> The safe entry used to be the "no amdgpu" fallback. In practice the user always picks the hwaccel entry, and even the safe entry needs `amdgpu.modeset=1 video=efifb:off` to bind the patched module properly (without them, amdgpu falls back to simpledrm and EGL enumeration silently breaks). So the essential flags live in [default], and the hwaccel entry adds nothing extra beyond the plymouth disable.

The hwaccel entry now only carries `plymouth.enable=0`. Debug spam (`loglevel=7 ignore_loglevel console=tty1`) is dropped from the live cmdline.

## Why this commit matters

Without this commit, even the safe Limine entry falls back to simpledrm (because `amdgpu.modeset=1` is only on the hwaccel entry). Simpledrm doesn't expose EGL contexts, so any Hyprland session started on the safe entry deadlocks in libhyprgraphics during initServer. By moving the KMS flags to `[default]`, every boot is real hwaccel from the moment `amdgpu.ko` loads — there's no path back to simpledrm on this hardware.
