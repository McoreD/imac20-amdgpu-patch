# 2026-09-26 iMac20,1 (T2) Amdgpu + Hyprland + libhyprgraphics Postmortem

## TL;DR

Multi-hour debugging session around a Hyprland deadlock when amdgpu KMS is active. Root cause is libhyprgraphics 0.5.1-4's async asset gatherer — Thread 2 parks on `pthread_cond_clockwait` while Thread 1 (`CCompositor::initServer`) throws because the condvar never signals. Fix is still upstream (filed: <https://github.com/hyprwm/hyprgraphics/issues/51>); local workaround forces Mesa to llvmpipe via `/etc/environment`. Repeated deadlocks also tripped Hyprland safe-mode, which I confused with the user config working — bind count was misleading. Recovered via `pkill -TERM Hyprland`. Avoid `systemctl --user restart` on a graphical session.

## Problems encountered

### P1. libhyprgraphics 0.5.1-4 deadlock in `CAsyncResourceGatherer::asyncAssetSpinLock`

- **Symptom**: 5 Hyprland SIGABRTs during `CCompositor::initServer` on a single session.
- **Stack** (from `gdb` + debuginfod on PID 3192):
  - Thread 1: in initServer; throws C++ exception → `__cxa_throw` → `std::terminate` → `abort`.
  - Thread 2: parked in `asyncAssetSpinLock()` on `pthread_cond_clockwait`. No one ever signals.
- **Reproduction**: every iMac20,1 T2 boot with `amdgpu.modeset=1` + libhyprgraphics 0.5.1-4 + Hyprland 0.56.2 + Mesa 26.2.2. Independent of Hyprland user config — even the 4-line greeter config deadlocks.
- **Workaround** (live in `/etc/environment`): `LIBGL_ALWAYS_SOFTWARE=1` + `MESA_LOADER_DRIVER_OVERRIDE=llvmpipe`.
- **Status**: Unfixed. Upstream: <https://github.com/hyprwm/hyprgraphics/issues/51>.

### P2. Hyprland safe-mode after multiple crashes

- **Symptom**: After 3+ Hyprland SIGABRTs in a short window, watchdog flips to `--safe-mode`. Next Hyprland start runs with `--safe-mode` flag and loads autogenerated fallback config. Banner: *"Warning: You're using an autogenerated config!"*
- **Detection**: `ps -eo args | grep Hyprland` shows `--safe-mode` flag, OR `hyprctl instances` reports a single instance but `hyprctl binds` count is suspiciously low (~228 with no `--safe-mode` confusion vs. real bind count).
- **Fix**: `pkill -TERM Hyprland` — uwsm wrapper respawns without `--safe-mode`.
- **Don't do**: `systemctl --user restart` on a running graphical session — cancels the service unit and bounces you to SDDM greeter (see P3 session-history).

### P3. Misleading "bind count" reports while I was debugging

- **Symptom**: Multiple times I told the user "228 binds, no config errors" and treated that as proof Option A was working. It wasn't — Hyprland was in safe-mode (`--safe-mode` flag on the running PID 5642), and the autogenerated fallback config had its own bind set.
- **Lesson**: bind count is unreliable evidence of "your config loaded". Always check `ps -eo args | grep Hyprland` for `--safe-mode` first.

### P4. Limited keybinds from anti-deadlock minimal config

- **Symptom**: Only 71 binds at first (user's custom overrides: Agent, MiniMax Agent, Screenshot, Photon panel). Missing SUPER+Q close, SUPER+Enter terminal, SUPER+E files, SUPER+D launcher, SUPER+F fullscreen, SUPER+1-9 workspaces, PrintScreen screenshot, etc.
- **Why**: My anti-deadlock minimal `hyprland.lua` skipped `require("default.hypr.omarchy")` because that call cascade-loads `default.hypr.looknfeel`, which is the gatherer trigger.
- **Fix (Option A applied 10:58)**: Explicitly require the bind modules individually — pure `hl.bind()` calls, no asset loading. The 6 lines:
  ```lua
  require("default.hypr.bindings.media")
  require("default.hypr.bindings.clipboard")
  require("default.hypr.bindings.tiling")
  require("default.hypr.bindings.utilities")
  local require_optional = require("default.hypr.require_optional")
  require_optional.module("default.hypr.bindings.voxtype")
  require_optional.module("default.hypr.bindings.applications")
  require("default.hypr.windows")
  ```
- **Result**: 228 binds, no deadlock, no config errors.
- **Configs**: `~/.config/hypr/hyprland.lua` (4043 bytes), `~/.config/hypr/autostart.lua` (793 bytes). ### P5. Quickshell taskbar not displaying

- **Symptom**: Top bar (Omarchy shell) absent from screen.
- **Misconception to clear**: Omarchy uses **Quickshell** (not Waybar). Waybar is a separate alt-bar; neither is installed unless you install one. **Quickshell is a Wayland client** — it asks Hyprland to render its pixels, like Discord does. It can't deadlock the compositor. The compositor deadlock (P1) is Hyprland's own code path inside libhyprgraphics.
- **Why it's not up**: `omarchy-launch-shell` is normally fired by `default.hypr.autostart` (which I skipped in P4). Manually re-launching from my OpenClaw exec failed 4 times — `WAYLAND_DISPLAY` and `HYPRLAND_INSTANCE_SIGNATURE` didn't propagate, so Qt defaulted to xcb and SIGABRT'd.
- **Fix paths** (in order of least disruption):
  1. Run `omarchy-launch-shell` from a user terminal (Foot). The terminal inherits your graphical session env, Quickshell comes up.
  2. `dbus-update-activation-environment --systemd WAYLAND_DISPLAY=wayland-1 XDG_SESSION_TYPE=wayland` — propagates env via dbus into `systemd --user`. Then Hyprland's `o.exec_on_start("omarchy-launch-shell")` works from the autostart context.
  3. Reboot — autostart fires from inside Hyprland's IPC context with full env. Heavy hand for a config tweak.
- **Status**: 4 quickshell SIGABRTs from failed attempts. User didn't reboot. Bar still not up.

## Lessons

1. **Don't `systemctl --user restart` a graphical session** — it cancels the service unit and bounces you to SDDM greeter. `pkill -TERM Hyprland` is the safer reset.
2. **Bind count is not proof of config loaded.** Always check `ps -eo args | grep Hyprland` for `--safe-mode` first.
3. **OpenClaw exec context doesn't have `WAYLAND_DISPLAY` / `HYPRLAND_INSTANCE_SIGNATURE`.** Spawning GUI processes from there is fraught. Use `dbus-update-activation-environment` to propagate env, or tell the user to run from a terminal.
4. **Wayland clients ≠ compositor.** Waybar / Quickshell / Discord / Foot can't deadlock Hyprland. Compositor deadlocks are the compositor's own responsibility.
5. **`/etc/environment` is loaded by PAM**, not by Hyprland. Changes require session restart to take effect for compositor subprocesses.
6. **Limine cmdline lives in the `.cmdline` PE section inside the `.efi`**, not in `/boot/limine.conf`. Extract with `objcopy --only-section=.cmdline -O binary <efi>`.
7. **Kernel modules have a `localversion`** that must match the running kernel. Forget to bump → modprobe refuses to load (vermagic mismatch).
8. **Don't take aggressive actions** (reboot, force restart) when a config tweak is the actual problem. Ask first, work light first.
